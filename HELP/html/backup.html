Sao lưu và phục hồi cho quản trị CSDL

Phân biệt cài lại và phục hồi

Bộ SQL cài mới chỉ tái tạo cấu trúc và dữ liệu mẫu. Muốn giữ đơn, tài khoản và chứng từ đã phát sinh, cần backup CSDL. Ảnh/chữ ký nằm trong SRC/backend/uploads cần sao lưu riêng cùng mốc; backup SQL không chứa các tệp này.

Thực hành script có sẵn

  1. Mở SQL/CSDL_HomeFix_SaoLuuPhucHoi.sql trong SSMS và bật Query → SQLCMD Mode.
  2. Sửa TenCSDL đúng nguồn HomeFix đang muốn sao lưu. Tài khoản cần quyền BACKUP/RESTORE; dịch vụ SQL cần quyền ghi thư mục đích.
  3. Giữ ThucHienPhucHoi=0 để tạo Full/Diff/Log và VERIFYONLY. Script chuyển recovery model sang FULL.
  4. Để thử phục hồi, đặt ThucHienPhucHoi=1. Đích là tên nguồn có hậu tố _Restore và phải chưa tồn tại. Script không ghi đè nguồn.
  5. Kiểm tra thông báo, trạng thái ONLINE và CHECKDB; đối chiếu số lượng dữ liệu/số dư. Không coi việc tạo được file .bak là đã phục hồi thành công.

Trình tự

Full WITH MOVE, NORECOVERY → Diff WITH NORECOVERY → Log WITH RECOVERY. Diff cần đúng bản Full nền; các bản Log phải liên tục. Bộ cài chuẩn có một file dữ liệu và một file log; cấu trúc nhiều file cần cấu hình MOVE thủ công.

Khi cần đưa bản phục hồi vào sử dụng

  1. Dừng các thao tác ghi nghiệp vụ và giữ bản hiện trạng nếu còn truy cập được.
  2. Phục hồi sang CSDL mới, khôi phục uploads tương ứng và bảo vệ file cấu hình.
  3. Kiểm tra đơn, thanh toán, ví, quyền và ảnh qua ứng dụng.
  4. Chỉ sau khi kiểm tra đạt mới đổi DB_NAME, khởi động lại API và cho người dùng tiếp tục.

Script không tự lập lịch. Có thể dùng Task Scheduler gọi sqlcmd trên Express. Lịch Full tuần, Diff ngày, Log 15 phút là đề xuất, cần giám sát và thử phục hồi định kỳ. STOPAT có ví dụ trong SQL nhưng chưa nằm trong bài test tự động.
